# MODEL.md

## Overview

The application is designed to ingest ESG-related activity data from multiple enterprise sources, normalize it into a common schema, and provide an analyst review workflow before audit sign-off.

The data model focuses on:

* Multi-tenancy
* Source traceability
* Scope 1, Scope 2, and Scope 3 categorization
* Unit normalization
* Analyst review workflow
* Audit trail generation

---

# Core Entities

## 1. Organization

Represents a tenant company using the platform.

### Fields

* id
* name
* industry
* created_at

### Purpose

Supports multi-tenancy by ensuring all ESG data belongs to a specific organization.

### Example

* Demo Enterprise
* Manufacturing Company A
* Retail Company B

---

## 2. DataSource

Represents an ingestion event and stores metadata about uploaded source files.

### Fields

* id
* organization
* source_type
* uploaded_file
* uploaded_at
* uploaded_by

### Supported Source Types

* SAP
* Utility
* Travel

### Purpose

Provides source-of-truth tracking and ingestion history.

Every emission record can be traced back to the exact source file that created it.

---

## 3. EmissionRecord

Represents a normalized ESG activity record.

### Fields

* id
* organization
* source
* category
* scope
* activity_value
* original_unit
* normalized_value
* normalized_unit
* suspicious
* status
* created_at

### Status Values

* pending
* approved
* rejected

### Purpose

Acts as the central normalized dataset used for reporting, analyst review, and auditing.

---

## Scope Categorization

### Scope 1

Direct emissions generated by company-owned operations.

Examples:

* Diesel consumption
* Petrol consumption
* Fuel usage

### Scope 2

Indirect emissions from purchased electricity.

Examples:

* Electricity consumption
* Utility usage

### Scope 3

Indirect emissions from business activities.

Examples:

* Flights
* Hotels
* Corporate travel

---

## Unit Normalization

Different sources can provide values in different formats and units.

The model stores both:

### Original Data

* activity_value
* original_unit

### Normalized Data

* normalized_value
* normalized_unit

This preserves the raw source information while enabling consistent analysis.

Examples:

| Original  | Normalized |
| --------- | ---------- |
| 500 L     | 500 L      |
| 2 MWh     | 2000 kWh   |
| 100 miles | 160.93 km  |

---

## 4. ReviewAction

Represents an analyst decision on a record.

### Fields

* id
* record
* action
* reviewer
* comments
* reviewed_at

### Supported Actions

* approved
* rejected

### Purpose

Captures review decisions and creates a review history.

---

## 5. AuditLog

Maintains a permanent audit trail.

### Fields

* id
* record
* action
* changed_by
* notes
* timestamp

### Example Events

* Record uploaded
* Record approved
* Record rejected
* Status updated

### Purpose

Ensures auditability and accountability for all record changes.

# Analyst Workflow

1. Upload source file.
2. Create DataSource record.
3. Parse and normalize source data.
4. Create EmissionRecord entries.
5. Flag suspicious records.
6. Analyst reviews records.
7. Approve or reject records.
8. Generate AuditLog entries.
9. Lock approved records for audit reporting.

---

# Design Decisions

The model prioritizes:

* Simplicity
* Traceability
* Auditability
* Extensibility

The architecture can be extended to support:

* Additional ESG sources
* Role-based access control
* Emission factor calculations
* Automated anomaly detection
* Enterprise authentication systems

while preserving the same core data model.
